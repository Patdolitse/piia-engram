## Scope

v3.48.1 is a single-change performance patch on the retrieval hot path. The
search-time tokenizer (`_tokenize`) re-ran the full n-gram + alias expansion for
every field of every entry on every query. The pure work is hoisted into a
module-level `@lru_cache`d `_tokenize_cached(text, expand_aliases)` keyed only on
its inputs and the import-time-static alias tables, collapsing repeated
tokenization into a dict lookup.

There is no behavior change: the produced token set (including CJK
uni/bi/tri-grams and alias expansion) is identical, so ranking and all
search/recall outputs are unchanged. No new agent-facing MCP tool, no telemetry
schema change, no permission/governance change, no data migration, nothing
auto-published.

## Changes

- **perf(retrieval): memoize tokenization on the hot search path** —
  `src/piia_engram/retrieval.py`: new module-level `@lru_cache(maxsize=4096)`
  `_tokenize_cached`. `_tokenize` delegates to it and returns a fresh `set` copy
  (callers like `_score_item` mutate via `.update(...)`). Read-only consumers
  (`_score_item` field intersection, `_bigram_similarity`) consume the cached
  `frozenset` directly to skip the defensive copy.

## Release Notes Draft

### English

Engram v3.48.1 is a performance patch. The search-time tokenizer is now
memoized: `_tokenize` delegates to a process-wide `@lru_cache`d pure function
keyed on the input text and the static alias tables, so the repeated n-gram +
alias work that previously ran for every field of every entry on every query
collapses into a dict lookup. Warm full-corpus keyword search drops from ~53ms
to ~20ms median (−62%).

There is no behavior change — token sets, alias expansion, and ranking are
identical. No telemetry schema, remote service behavior, permission
enforcement, user-data migration, or new agent-facing MCP tool changes in this
release.
