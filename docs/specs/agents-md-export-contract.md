# AGENTS.md / CLAUDE.md export contract

Status: **helper + CLI implemented + tested** (`src/piia_engram/agents_md_export.py`,
`tests/test_agents_md_export.py`, plus the `engram export-agents-md` CLI in
`setup_wizard.py` covered by `tests/test_export_agents_md_cli.py`). A dedicated
MCP tool is still intentionally deferred (the CLI is owner-run and sufficient; a
new agent-facing surface would need its own governance review).

## Purpose

Let a user drop verified, generalizable Engram knowledge into an `AGENTS.md` or
`CLAUDE.md` so any tool reading those files inherits the same durable context —
safely. These files are frequently committed to repos, so the export is
conservative by construction.

## Guarantees (enforced by tests)

| Guarantee | Rule |
|-----------|------|
| Verified-only | `tier == "verified"` and `status == "active"` |
| No staging | staging entries are excluded |
| No sensitive/private | `sensitivity.classify_item` rank must be `<= max_sensitivity` (default `work`); `private`/`secret` excluded, including value-floor detection of credential-shaped content |
| Metadata/summary-only | emits summary/choice + domain; never ids, access_count, risk flags, or provenance internals |
| Project/global separation | `scope="global"` → only non-project knowledge; `scope="project"` → only the named project |
| Honest banner | output carries a "Generated by Engram … staging/sensitive excluded" comment |

## API

```python
build_agents_md_export(*, lessons, decisions, scope="global", project="",
                       max_sensitivity="work", heading=...) -> str
select_exportable(entries, *, scope, project, max_sensitivity) -> list[dict]
```

Both are pure functions over already-loaded entries; they do not touch the store.

## Follow-up (separate review)

1. ✅ **Implemented** — the `engram export-agents-md [--scope ...] [--project ...]
   [--max-sensitivity ...] [--out PATH]` CLI subcommand loads entries and calls
   `build_agents_md_export`. It is owner-run (local CLI), prints to stdout by
   default, and refuses to overwrite an existing file with `--out`. A separate
   MCP tool remains deferred (would need `export_owner_only` governance review).
2. Apply the same verified-only + non-staging filter to `export_engram`, which
   today includes staging items (see the Permission Profile vNext design §3 and
   the explore findings). That change needs its own tests + review because it
   alters an existing export's contents.

## Non-goals

- Not a full backup format (that is `export_engram`); this is a curated,
  committable knowledge digest.
- No write-back / import side — this is export-only.
