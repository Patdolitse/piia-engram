# Engram 对外传播话术

> 的措辞应从这里取用，保持一致。

---

## 核心痛点（开场必说）

现在 AI 工具都很聪明，但它们不认识你。

每换一个工具、一个会话、一个项目，你都要重新解释自己是谁、项目到哪一步、哪些坑已经踩过。你在 Claude Code 里积累的经验，Codex 不知道。你在 ChatGPT 里做的决策，下次对话就忘了。

**你的 AI 协作知识在反复归零。**

---

## 一句话定位

Engram 是你的 AI 记忆印记——把"我是谁、我如何工作、我的项目为什么这样决策"持久化为本地资产，让不同 AI 工具共享同一个用户上下文。

---

## 标语

**不是另一个 Agent OS，而是所有 Agent OS 都应该接入的记忆印记。**

---

## 它是什么 / 不是什么

| Engram 是 | Engram 不是 |
|-------------|--------------|
| 个人 AI 身份和知识的本地存储 | 又一个 AI 聊天工具 |
| 所有 AI 工具的记忆后端 | 某一个 AI 平台的插件 |
| 你可以带走、编辑、备份的资产 | 被锁在云端的用户数据 |
| MCP 标准协议，任何 AI 都能接入 | 私有格式，只在一个工具里用 |

---

## 核心价值主张（三点）

1. **跨工具记忆** — Claude Code 里存的教训，Codex 下次对话就能用。换工具不丢知识。
2. **冷启动秒懂你** — 新对话、新项目、新工具，AI 第一句话就知道你是谁、偏好什么、踩过哪些坑。
3. **数据主权** — 全部存在本地 `~/.engram/`，JSON/Markdown 格式，人可读可编辑。你的记忆属于你。

## 5 分钟 Demo 剧本

### 场景 A：没有 Engram（对照组）

> 用户："帮我写一个函数检查文件是否存在"
>
> AI 回复英文、加冗长 docstring、不知道用户的质量标准、不知道 Windows python stub 的坑。

### 场景 B：接入 Engram

> 同一个问题，AI 自动用中文、简洁实用、用 Path 避坑、知道用户是非技术背景。
>
> 因为 Engram 在对话开始时就告诉了 AI：你是谁、你怎么工作、你踩过什么坑。

### 场景 C：跨工具共享

> Claude Code 里记录的教训 → Codex 里直接可用。
> 同一个 MCP 接口，两端配置一致，知识实时共享。

### 场景 D：身份卡（兜底方案）

> 不支持 MCP？没关系。导出一张 Markdown 身份卡，粘贴到任何 AI 对话开头。
> 即使是 ChatGPT、Kimi、Gemini，也能立刻了解你。

## 目标用户

**高频多 AI 工具用户** — 同时用 Claude Code + Codex（或 Cursor/Copilot/ChatGPT 等多个工具），
每天在不同 AI 之间切换，反复解释自己和项目的人。

不是大众市场产品。是给"AI 重度用户"解决一个真实痛点。

---

## 竞品定位

| 层级 | 产品 | 关系 |
|------|------|------|
| 底座层 | Claude Code, Codex, Cursor | Engram 坐在它们下面，提供记忆 |
| 编排层 | Slock, Multica, OpenClaw | Engram 为它们提供用户上下文 |
| 记忆层 | **Engram** | 这里目前是空白市场 |

不竞争，互补。Engram 做的事情是这些工具都需要但都没做的：持久化的、跨平台的、用户拥有的个人 AI 身份。

---

## 不要说

- "Engram 是个人智能身份资产系统" — 冷用户听不懂，太抽象
- "AI 知识库" — 和 Notion/Obsidian 混淆，Engram 存的是身份不是文档
- "Agent OS" — 和 OpenClaw/Slock 定位冲突，我们不做编排
- "比 Claude 记忆更好" — 不攻击平台方，强调互补

## 要说

- "AI 不认识你" — 痛点共鸣
- "换工具不丢知识" — 具体场景
- "你的记忆属于你" — 数据主权
- "5 分钟配置，两个工具同时认识你" — 低门槛
- "本地存储，JSON 格式，你可以直接打开看" — 透明可信
